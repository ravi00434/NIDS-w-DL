3. DATA FLOW ARCHITECTURE
===============================================================================

REAL-TIME PROCESSING PIPELINE:

Step 1: TRAFFIC GENERATION/CAPTURE
┌──────────────────────────────────┐
│  FastTrafficGenerator            │
│  - Generates network flow data   │
│  - Simulates normal/attack       │
│  - Adds metadata & timestamps    │
└──────────────────────────────────┘
                ↓
Step 2: FEATURE EXTRACTION
┌──────────────────────────────────┐
│  extract_features()              │
│  - Parse 42 network features     │
│  - Convert to numerical array    │
│  - Handle missing values         │
└──────────────────────────────────┘
                ↓
Step 3: NORMALIZATION
┌──────────────────────────────────┐
│  StandardScaler                  │
│  - Load nids_scaler.pkl          │
│  - Scale features (mean=0, std=1)│
│  - Prepare for neural network    │
└──────────────────────────────────┘
                ↓
Step 4: QUEUE MANAGEMENT
┌──────────────────────────────────┐
│  Input Queue (max 1000)          │
│  - Collect flows into batches    │
│  - Batch size: 32 flows          │
│  - Thread-safe operations        │
└──────────────────────────────────┘
                ↓
Step 5: GPU BATCH PROCESSING
┌──────────────────────────────────┐
│  Neural Network Inference        │
│  - Load batch to GPU memory      │
│  - Parallel processing (2000+    │
│    CUDA cores)                   │
│  - Get predictions (0-1)         │
└──────────────────────────────────┘
                ↓
Step 6: CLASSIFICATION
┌──────────────────────────────────┐
│  Threshold Decision              │
│  - If prediction > 0.5: Attack   │
│  - If prediction ≤ 0.5: Normal   │
│  - Calculate confidence score    │
└──────────────────────────────────┘
                ↓
Step 7: ALERT GENERATION
┌──────────────────────────────────┐
│  Alert Manager                   │
│  - Generate alert if attack      │
│  - Assign severity level         │
│  - Log to file & console         │
└──────────────────────────────────┘
                ↓
Step 8: RESULT DELIVERY
┌──────────────────────────────────┐
│  Output Queue                    │
│  - Store results with metadata   │
│  - Send to web dashboard         │
│  - Update statistics             │
└──────────────────────────────────┘
                ↓
Step 9: VISUALIZATION
┌──────────────────────────────────┐
│  Web Dashboard / CLI             │
│  - Display real-time stats       │
│  - Show alerts                   │
│  - Update graphs                 │
└──────────────────────────────────┘

THROUGHPUT: 1000+ flows/second (GPU), 40 flows/second (CPU)
LATENCY: <1ms per prediction
QUEUE SIZE: Max 1000 flows in memory

5. GPU ACCELERATION ARCHITECTURE
===============================================================================

GPU PROCESSING PIPELINE:

┌─────────────────────────────────────────────────────────────────────┐
│                        CPU MEMORY                                    │
│  ┌────────────────────────────────────────────────────────────┐    │
│  │  Network Flow Data (Python Objects)                        │    │
│  │  - Flow 1, Flow 2, ..., Flow 32 (Batch)                    │    │
│  └────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────┘
                              ↓ (Memory Transfer)
┌─────────────────────────────────────────────────────────────────────┐
│                        GPU MEMORY (VRAM)                             │
│  ┌────────────────────────────────────────────────────────────┐    │
│  │  Tensor Data (NumPy Arrays → GPU Tensors)                  │    │
│  │  Shape: (32, 42) - 32 flows × 42 features                  │    │
│  └────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│                    CUDA PARALLEL PROCESSING                          │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  CUDA Cores (896 cores on GTX 1650)                          │  │
│  │                                                                │  │
│  │  [Core 1] [Core 2] [Core 3] ... [Core 896]                   │  │
│  │     ↓        ↓        ↓              ↓                        │  │
│  │  Matrix Multiplications (Parallel)                            │  │
│  │  - Layer 1: 42 × 256 = 10,752 operations                     │  │
│  │  - Layer 2: 256 × 128 = 32,768 operations                    │  │
│  │  - Layer 3: 128 × 64 = 8,192 operations                      │  │
│  │  - Layer 4: 64 × 32 = 2,048 operations                       │  │
│  │  - Layer 5: 32 × 1 = 32 operations                           │  │
│  │                                                                │  │
│  │  Total: ~54,000 operations per flow × 32 flows               │  │
│  │       = ~1.7 million operations per batch                     │  │
│  │                                                                │  │
│  │  Processing Time: ~4ms per batch (GPU)                        │  │
│  │  vs ~100ms per batch (CPU)                                    │  │
│  └──────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        GPU MEMORY (Results)                          │
│  ┌────────────────────────────────────────────────────────────┐    │
│  │  Prediction Tensor                                          │    │
│  │  Shape: (32, 1) - 32 predictions                            │    │
│  │  Values: [0.12, 0.89, 0.34, ..., 0.67]                      │    │
│  └────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────┘
                              ↓ (Memory Transfer)
┌─────────────────────────────────────────────────────────────────────┐
│                        CPU MEMORY (Results)                          │
│  ┌────────────────────────────────────────────────────────────┐    │
│  │  Python List/Dict                                           │    │
│  │  [{'is_attack': False, 'confidence': 0.88},                 │    │
│  │   {'is_attack': True, 'confidence': 0.89}, ...]             │    │
│  └────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────┘

GPU OPTIMIZATION TECHNIQUES:

1. MEMORY GROWTH
   - Dynamic GPU memory allocation
   - Prevents out-of-memory errors
   - Code: tf.config.experimental.enable_memory_growth = True

2. BATCH PROCESSING
   - Process 32 flows simultaneously
   - Minimizes CPU↔GPU transfers
   - Maximizes GPU utilization

3. THREAD OPTIMIZATION
   - Inter-op parallelism: Auto
   - Intra-op parallelism: Auto
   - TensorFlow manages thread pool

4. MIXED PRECISION (Optional)
   - FP16 for speed, FP32 for accuracy
   - Reduces memory usage
   - Increases throughput

PERFORMANCE METRICS:
- GPU Utilization: 95%+
- Memory Usage: ~500MB VRAM
- Speedup: 24x over CPU
- Throughput: 1000+ flows/second

NETWORK FLOW STRUCTURE:

Each network flow contains:
├── Connection Metadata
│   ├── src_ip: Source IP address
│   ├── dst_ip: Destination IP address
│   ├── src_port: Source port
│   ├── dst_port: Destination port
│   └── timestamp: Flow timestamp
│
├── 42 Network Features
│   ├── Duration & Protocol
│   ├── Packet Statistics
│   ├── Byte Counts
│   ├── Timing Information
│   ├── TCP Characteristics
│   └── Behavioral Indicators
│
└── Ground Truth (for testing)
    └── actual_attack: True/False label

   - Controller: Flask routes and API

   - Consumer: Batch processor

   - Single NIDS engine instance
   - Shared configuration manager

5. OBSERVER PATTERN
   - Web dashboard observes NIDS engine
   - Real-time updates via polling/WebSocket

6. FACTORY PATTERN
   - Traffic generator creates flow objects
   - Model loader creates AI model instances

7. STRATEGY PATTERN
   - Multiple model options (DL vs RF)
   - Configurable detection strategies

DESIGN DECISIONS & RATIONALE
===============================================================================

1. WHY PYTHON?
   ✓ Rich ML/AI ecosystem (TensorFlow, scikit-learn)
   ✓ Rapid development and prototyping
   ✓ Excellent GPU support via CUDA
   ✓ Large community and libraries

2. WHY TENSORFLOW?
   ✓ Industry-standard deep learning framework
   ✓ Excellent GPU acceleration
   ✓ Production-ready deployment
   ✓ Keras integration for ease of use

3. WHY FLASK?
   ✓ Lightweight and flexible
   ✓ Easy to integrate with Python backend
   ✓ RESTful API support
   ✓ Suitable for small to medium applications

4. WHY BATCH PROCESSING?
   ✓ Maximizes GPU utilization
   ✓ Reduces CPU↔GPU memory transfers
   ✓ Improves throughput significantly
   ✓ Industry best practice

5. WHY DUAL MODELS (DL + RF)?
   ✓ Fallback option when GPU unavailable
   ✓ Ensemble voting for higher accuracy
   ✓ Comparison and validation
   ✓ Different strengths for different scenarios

6. WHY SIMULATED TRAFFIC?
   ✓ Safe for demonstration and testing
   ✓ No network permissions required
   ✓ Controlled attack scenarios
   ✓ Easy to reproduce results

===============================================================================
LIMITATIONS & CONSTRAINTS
===============================================================================

CURRENT LIMITATIONS:

1. Simulated Traffic Only
   - Not capturing real network packets
   - Requires integration with Scapy/pcap for production

2. Single GPU Support
   - No multi-GPU distribution
   - Limited to single machine throughput

3. No Authentication
   - Web dashboard accessible without login
   - Suitable for local/demo use only

4. Limited Attack Types
   - Trained on UNSW-NB15 attack categories
   - May not detect novel zero-day attacks

5. No Automated Response
   - Detection only, no blocking/mitigation
   - Requires manual intervention

SYSTEM CONSTRAINTS:

1. Hardware Requirements
   - NVIDIA GPU required for optimal performance
   - Minimum 4GB RAM, 8GB recommended
   - 10GB disk space for environment

2. Network Constraints
   - Demo mode: No real network access
   - Production: Requires network tap/mirror port

3. Scalability Constraints
   - Single instance: ~1000 flows/second
   - Requires load balancing for higher throughput
